# Стиль экрана: как говорит Добрик

Каждое сообщение бота — это **карточка**: сверху факты, снизу живая реплика героя.
Участник должен за три секунды понять, где он и что делать дальше.

## Скелет экрана

```
📅 <b>Заголовок</b>
<i>подзаголовок: период, статус, уточнение</i>

<b>Блок 1</b>
💌 Название
<b>200</b> баллов · ✅ зачтено

<b>Блок 2</b>
…

🤗 <b>Добрик</b>
▏Что это значит и что делать дальше.
▏Одна короткая подсказка про кнопки.
```

1. **Заголовок** — эмодзи + жирный текст. Одна строка, без точки в конце.
2. **Подзаголовок** — курсив, служебная информация (период, «неделя закрыта», отдел).
3. **Пустая строка** отделяет шапку от содержимого и содержимое от реплики Добрика.
4. **Блоки** нумеруются словами, понятными участнику: «Задание 1», «Неделя 2», а не кодами из базы.
5. **Реплика Добрика** — всегда последняя, через `voice()`. Две-три коротких фразы:
   что сейчас, сколько можно получить, какую кнопку нажать.

## Строки с данными

Для «метка: значение» есть `row()`:

```python
row("⭐", "Мои баллы", num(points), f"место #{rank} из {total}")
# ⭐ Мои баллы: <b>200</b> · место #14 из 33
```

- значение — всегда `<b>жирное</b>`;
- второстепенное — после `·`;
- числа больше тысячи — через `num()`: `1 400`;
- слова согласуются через `plural()`: «1 балл», «2 балла», «5 баллов»;
- даты — через `_date_ru()` и `week_period()`: «с 9 по 15 сентября», не «09.09–15.09».

## Голос Добрика

Он помощник, а не диктор. В каждой реплике:

- **говорит о результате**, а не о механике: «можно заработать 1 400 баллов»,
  а не «доступно 4 задания»;
- **подсказывает следующий шаг**: «нажми на задание — расскажу условия»;
- **мотивирует по ситуации**: ноль отчётов — «возьми хотя бы одно, этого достаточно»;
  всё сдано — «четыре из четырёх, снимаю шляпу»;
- **никогда не пугает и не обвиняет**. Отказ P&C — «это поправимо, доснимай и отправляй снова».
- **не пишет про кнопки, которых нет** на этом экране.

Запрещено: канцелярит («осуществляется», «необходимо выполнить»), технические слова
(«callback», «id», «статус: pending»), восклицательные знаки пачками.

## Пошаговые задания

Отчёт собирается по шагам: один экран — один шаг, чтобы участнику не приходилось
держать в голове весь список условий.

- шаги описаны в `data/tasks.json` (`steps` у задания и у каждого варианта);
- у шага четыре поля: `kind` (`photo` / `file` / `note`), `title` (что прислать),
  `need` (что именно должно быть видно), `help` (реплика Добрика);
- экран шага показывает «Шаг N из M», требование, полосу пройденных шагов и подсказку;
- прислали не то (текст вместо фото) — бот не молчит, а объясняет, что нужно на этом шаге;
- после последнего шага — экран «Отчёт готов» со всем собранным и кнопкой отправки;
  любой шаг можно открыть заново и переснять.

Новое задание без `steps` работает по-старому (общий экран со списком условий),
но лучше сразу описать шаги.

## Кнопки

- подпись короткая, 1–3 слова: «Задание 1», «В меню», «Отправить на проверку»;
- первая кнопка — то, что участник должен сделать сейчас (`style="primary"`);
- подтверждение — `style="success"`, отказ и дисквалификация — `style="danger"`;
- эмодзи в начале подписи выносится в иконку автоматически (`emoji.button_icon`),
  писать его в тексте — правильно, вручную ничего выносить не нужно;
- последняя кнопка экрана — возврат: «⬅️ В меню» или «⬅️ Назад».

## Эмодзи

Обычных эмодзи в боте нет: любой символ заменяется премиальным при отправке
(`app/emoji.py`). Поэтому в текстах пишутся обычные символы — это и есть запасной вариант.
Если нужного символа нет в наборах, добавьте замену в `SUBSTITUTES`, иначе упадёт
проверка `check_no_plain_emoji` в `scripts/smoke_test.py`.

В каналах модерации эмодзи остаются обычными — Telegram не принимает там премиальные.

## Длина

- сообщение — до 4096 символов, подпись под фото — до 1024;
- длинные перечисления (правила, условия зачёта) — в `quote(..., expandable=True)`:
  экран остаётся коротким, детали открываются нажатием;
- абзац пишется одной строкой, перенос делает Telegram; ручные переносы — только между
  смысловыми строками.

## Фильтры доступа

Фильтр в aiogram объявляется наследником `BaseFilter` (или обычной функцией). Объект
с методом `__call__` не годится: aiogram не дождётся корутины и посчитает проверку
пройденной — так панель P&C однажды открылась всем. Проверять доступ нужно прогоном
обновления через диспетчер, а не вызовом фильтра напрямую.

## Проверка

После правки текстов:

```bash
python -m scripts.preview          # прочитать все экраны глазами
python -m scripts.smoke_test       # бизнес-логика, права, эмодзи, миграции
python -m scripts.audit_texts      # HTML и лимиты длины на каждом экране
python -m scripts.audit_callbacks  # все кнопки от имени админа, P&C и участника
python -m scripts.audit_rules      # правила марафона на живых данных
python -m scripts.audit_jobs       # каналы, фоновые задачи, экспорт, рассылки
```

В текстах сообщений `&` пишется как `&amp;` — это требование Telegram HTML.
В подписях кнопок, Excel и настройках — обычный `&`: там разметки нет.
