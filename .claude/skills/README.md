# Навыки проекта

`.claude/skills/*` — документы, которые Claude Code подключает сам, когда задача попадает
под описание навыка. Их же можно читать глазами: это рабочие стандарты.

| Навык | О чём | Переносится |
|---|---|---|
| `agent-workflow` | порядок работы: формат ответа, CHANGELOG, коммиты, проверки, материалы для людей | **да** |
| `tg-bot-style` | оформление экранов, голос героя, кнопки, эмодзи, лимиты, навигация | **да** |
| `tg-bot-kit` | каркас бота: структура, настройки, база, доступы, деплой, шесть проверок, грабли | **да** |
| `dobrik-style` | частности «Марафона добрых дел»: герой, недели, задания | нет, это про этот проект |

## Как перенести в новый проект

Глобально — навыки заработают во **всех** проектах на этом компьютере:

```bash
bash scripts/install_skills.sh
```

Только в один репозиторий:

```bash
bash scripts/install_skills.sh /путь/к/новому/проекту
```

Копируются три переносимых навыка, `dobrik-style` остаётся здесь.

## Что делать в новом проекте

1. Поставить навыки командой выше.
2. Положить в корень `CLAUDE.md` — шаблон в `tg-bot-kit/references/starter.md`, раздел 9.
3. Собирать бота по `tg-bot-kit` → «Порядок работы над новым ботом»; готовый каркас
   по шагам — в `references/starter.md`, заготовки шести проверок — в `references/checks.md`.
4. Завести свой узкий навык вместо `dobrik-style`: имя героя, сущности предметной
   области, особые правила. Общее не дублировать — сослаться на него.

## Как писать навык

- один файл `SKILL.md` с заголовком `name` и `description`;
- `description` объясняет **когда** навык нужен, а не только о чём: по нему принимается
  решение о подключении. Перечисляйте поводы: «новый бот», «правка текста», «ошибка»;
- длинные подробности — в `references/*.md`, на них ссылается `SKILL.md`;
- правило записывается вместе с причиной: почему иначе нельзя. Правило без причины
  через полгода нарушают первым;
- в переносимом навыке нет названий этого проекта — только примеры в кавычках.

Проверка: `python -m scripts.audit_skills` — заголовки, имена, ссылки на справочники,
привязка к проекту и работоспособность установщика.
