# Порядок работы агента

Правила выработаны на боевом проекте. Действуют в любом проекте, независимо от темы.

## Формат ответа

**Строго и по делу. Без воды и без технических данных. Строго по пунктам.**

Два раздела, всегда в этом порядке:

```
**Что добавил**
1. …
2. …

**Что сделать вам**
1. …
2. …
```

- пункт — одно законченное изменение словами заказчика, а не именами функций;
- «Что сделать вам» — только те действия, которые агент выполнить не может:
  нажать в интерфейсе хостинга, задать секрет, создать канал, разослать людям;
- если делать ничего не нужно — так и написать одной строкой;
- не пересказывать код, не показывать диффы, не объяснять внутренности;
- о неудаче сообщать прямо: что не работает, почему, и что предлагается.

## Файл изменений

**После каждой правки** запись в `CHANGELOG.md`, сверху — самое свежее:

```markdown
## Короткое название (дата)

Одно предложение — зачем.

- что изменилось;
- что это даёт человеку;
- что осталось за кадром и почему.
```

Исправление ошибки описывается через симптом, который видел заказчик, а не через
внутреннюю причину: «баллы не зачлись», а не «не хватало flush».

## Ветка и коммиты

- работать в ветке, указанной в задании; при её отсутствии — в `main`;
- пушить сразу после того, как проверки прошли, не накапливать;
- сообщение коммита — по-русски, одной строкой, о сути изменения;
- pull request создавать только по явной просьбе.

## Проверка перед сдачей

Ничего не сдаётся без прогона. Минимум:

1. линтер по всему коду;
2. автотесты бизнес-логики — на обеих базах, если проект работает и с SQLite, и с PostgreSQL;
3. аудиты интерфейса: все кнопки, длина и разметка всех экранов;
4. предстартовая проверка настроек.

Если правились навыки в `.claude/skills` — прогнать и их аудит: они должны остаться
переносимыми в следующий проект.

Новая возможность закрывается автотестом в том же коммите. Исправленная ошибка —
тоже: тест повторяет тот самый сценарий, в котором она проявилась.

## Чужие правки и старые решения

- файл изменился на диске — это текущее состояние, а не повод откатывать;
- решение, уже принятое заказчиком, не пересматривается и не обсуждается заново;
- возражение высказывается один раз, коротко; после подтверждения работа продолжается
  в полном объёме.

## Материалы для людей

Проект не закончен, пока у заказчика нет того, что можно показать команде:

- описание и картинки для профиля бота;
- презентация со скриншотами реальных экранов;
- памятка одним текстом — переслать в рабочий чат;
- тексты анонса для корпоративных каналов;
- список того, что нужно сделать руками перед запуском.

Скриншоты и картинки генерируются скриптом из живых текстов проекта — тогда они
не расходятся с ботом после первой же правки.
