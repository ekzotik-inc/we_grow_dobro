# Деплой и эксплуатация

## Render

- **blueprint `render.yaml`** описывает и сервис, и базу: развернуть проект заново —
  одна кнопка. `DATABASE_URL` подставляется через `fromDatabase`, руками не копируется.
- секреты (`BOT_TOKEN`, id каналов) — `sync: false`: задаются в интерфейсе, не в репозитории.
- бесплатный тариф усыпляет сервис после 15 минут без запросов: первое действие
  пользователя ждёт холодного старта. Для боевого запуска — платный инстанс.
- в `/api/health` полезно отдавать хеш коммита (`RENDER_GIT_COMMIT`): видно, доехал ли деплой.

## Цена базы

Постоянно работающему боту дешевле **фиксированный тариф Postgres у хостинга**, чем
«бессерверная» база с оплатой за часы: чтобы она не засыпала, её приходится будить
круглосуточно, и бесплатная квота сгорает за пару недель. Не платите за keepalive.

## Keepalive

Одна фоновая задача: `SELECT 1` в базу и запрос к собственному `/api/health`.
Интервал — по самому короткому засыпанию. Выключатель — переменная окружения:
на тарифе без засыпания задача не нужна.

## Часовой пояс

`TZ` задаётся явно, планировщик считает по нему. На системе без базы часовых поясов
код должен откатываться на UTC с предупреждением, а не падать при каждом экране.

## Переезд базы

Скрипт копирования «источник → приёмник» пишется заранее, а не в день переезда:
таблицы копируются в порядке зависимостей, счётчики последовательностей выставляются
по максимальному id.

## Что сделать руками перед запуском

`preflight` печатает этот список, но он один и тот же от проекта к проекту:

1. Платный инстанс, чтобы сервис не засыпал.
2. Токен и id каналов в переменных окружения.
3. Бот — администратор в обоих каналах, модераторы — участники каналов.
4. Справочники наполнены (команды, категории, периоды).
5. Описание, аватар и картинка описания в BotFather.
6. Контент включён в день старта.
