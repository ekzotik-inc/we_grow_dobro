# Грабли, на которые уже наступили

Каждая строка стоила отдельного разбора в бою.

## Доступ

- **Фильтр-класс с `__call__`.** aiogram не ждёт корутину такого объекта и считает
  проверку пройденной — панель открылась всем. Только `BaseFilter` или функция.
- **Роутер без фильтра.** У модерации фильтр забыли — кнопки в канале работали у всех,
  кто их видел. Фильтр вешается на роутер целиком: `router.callback_query.filter(...)`.
- **Команда в меню.** `/admin`, зарегистрированная глобально, видна всем. Нужны области
  видимости команд.
- **Флаг в базе.** Права, выданные когда-то флагом, переживают переезд и достаются не тем.
  Источник правды — список в настройках.

## База

- **Нет миграций — падает деплой.** Новая колонка в модели без автомиграции роняет бот
  на первом же запросе. Автомиграция обязана понимать JSON-колонки с `default=list`.
- **Устаревший состав после перевода.** Запрос без `populate_existing=True` отдаёт объект
  из кэша сессии вместе со старой коллекцией связанных записей — панель показывала
  человека в команде, из которой его уже перевели. Все запросы, читающие связь,
  которая меняется в том же процессе, должны перечитывать её принудительно.
- **Ленивое отношение после удаления.** Обращение к `team.members` после удаления строк
  даёт `MissingGreenlet`. В async-коде связи загружаются запросом явно.
- **Спящая база.** Первое обращение после простоя падает по таймауту. Нужен повтор
  с паузами, а не «попробуйте позже».

## Интерфейс

- **Недоступный идентификатор кастомного эмодзи ломает каждое сообщение с ним.**
  Набор присылает заказчик, и часть символов боту недоступна. Спрашивайте у Telegram
  (`getCustomEmojiStickers`) на старте, какие идентификаторы он знает, а остальные
  показывайте обычными. Плюс широкий перехват при отправке: формулировки отказа
  для текста и для иконки кнопки разные.

- **Кнопка без обработчика** выглядит как поломка. Ловится только автоматическим
  прогоном всех `callback_data`.
- **Подпись кнопки из одного эмодзи**: вынос иконки оставляет пустой текст, и Telegram
  отклоняет всю клавиатуру. Поэтому такая подпись остаётся с обычным эмодзи — рядом с
  премиальными кнопками разница заметна. Добавьте слово: «⬅️ Назад» вместо «⬅️».
- **Эмодзи в конце подписи** («Дальше ➡️») не становится иконкой: в неё выносится только
  первый символ. Ловится перебором всех подписей из файла клавиатур.
- **Подпись под фото** — 1024 символа, а не 4096. Длинный экран с картинкой не отправится.
- **Старые сообщения** с кнопками живут в чатах вечно. Нажатие на неактуальную кнопку
  обрабатывается вежливым ответом и возвратом в меню.
- **`ReplyKeyboardRemove` в удалённом сообщении** не снимает клавиатуру: она остаётся
  висеть навсегда.

## Мастера и файлы

- **Альбом** приходит несколькими апдейтами: без защиты по `media_group_id` фотографии
  расползаются по разным шагам.
- **Потерянный черновик.** Состояние в памяти + перезапуск = пропавшие фотографии.
  Черновик живёт в базе.
- **Двухшаговый ввод там, где хватает одного.** «Введите число» → «введите причину»
  выглядит как зависание: разбирайте оба значения из одного сообщения и давайте кнопку
  «без причины».

- **Подпись к фото, закрывающая чужой шаг.** Caption молча уходил в первый незакрытый
  текстовый шаг — участник присылал фото с подписью, и шаг «описание» считался
  выполненным чем попало. Подпись используется только там, где шагов нет вовсе.
- **Проверка типа в обработчике.** Пока она жила в обработчике, её обходили другие
  пути (восстановление черновика, альбом). Место такой проверки — сервис.

## Тесты

- **Подмена обработчиков без восстановления.** Роутеры — общие объекты процесса;
  тест-шпион, не вернувший оригиналы, молча ломает все последующие проверки.
- **Проверка прав вызовом фильтра** ничего не доказывает. Только прогон обновления
  через диспетчер.

## Правки

- **Слишком широкая замена.** Массовая замена строки по всему проекту задевает подписи
  кнопок, выгрузку и настройки. Экранирование HTML касается только текстов сообщений.
