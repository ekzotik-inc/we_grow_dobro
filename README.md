# We Grow Dobro — корпоративный Telegram-бот марафона добрых дел

Телеграм-бот для проведения 3-недельного марафона: регистрация участников **с модерацией**, команды по 5 человек,
задания недели (4 в неделю, 200–500 баллов, задания с двумя опциями), отправка отчётов (фото + заметка),
**проверка заявок и отчётов прямо в двух Telegram-каналах**, начисление баллов, командный рейтинг, дисквалификация,
**рассылки по сегментам участников** и экспорт в Excel.

## Два канала модерации

| Канал | Что приходит | Кнопки | Эффект |
|---|---|---|---|
| **Канал заявок** | анкета нового участника (ФИО, отдел, город, tg id) | ✅ Принять · ❌ Отклонить | до «Принять» участник **не может** вступить в команду и отправлять отчёты |
| **Канал результатов** | файлы отчёта + карточка (участник, команда, задание, условия зачёта, заметка) | ✅ Зачесть · ❌ Отклонить | **баллы начисляются только после «Зачесть»** |

Нажимает и админ, и любой сотрудник P&C (все, чьи id в `ADMIN_IDS`, плюс отмеченные админами в базе).
Посторонний, нажавший кнопку в канале, получает отказ. После решения бот **редактирует ту же карточку**
(`editMessageText`): кнопки исчезают, в тексте остаётся кто, когда и с какой причиной решил — канал становится журналом решений.
Участнику одновременно уходит уведомление в личку.

Если канал не подключён, карточки с теми же кнопками приходят всем P&C в личку — бот работает и без каналов.

Весь интерфейс бота построен на **inline-клавиатурах с редактированием сообщения**: по нажатию кнопки бот получает
`callback_query` и делает `editMessageText`/`editMessageCaption` того же сообщения (см. `app/bot/common.py: edit`).
Когда пользователь отвечает текстом или фото, бот удаляет его сообщение и обновляет своё «якорное» сообщение
(`edit_anchor`), поэтому чат не засоряется.

## Оформление сообщений

- **Премиум-эмодзи** из набора @d_code (`app/emoji.py`). Telegram разрешает их боту только пока
  у владельца бота есть Telegram Premium, и **никогда не разрешает в каналах** — поэтому каждый
  эмодзи хранится вместе с обычным символом, на который он молча заменяется. В карточках
  модерации всегда обычные. Если Premium закончится, бот сам перейдёт на обычные эмодзи
  и продолжит работать (`app/bot/middlewares.py`). Выключить заранее: `PREMIUM_EMOJI=0`.
- **Голос бота.** Реплики от лица помощника (`VOICE_NAME`, по умолчанию «Добрик») выводятся
  цитатой под данными — как в примере из прошлого проекта.
- **Посмотреть все экраны, не запуская бота:** `python -m scripts.preview` — печатает
  приветствие, меню, задания, отчёт, рейтинг и рассылки на живых данных.

## Стек

- Python 3.10+, [aiogram 3](https://docs.aiogram.dev) (бот, long polling), FastAPI + uvicorn (служебный порт для хостинга),
  SQLAlchemy 2, APScheduler (анонсы/напоминания), openpyxl (экспорт).
- **База:** SQLite-файл локально, PostgreSQL на хостинге — переключается одной переменной `DATABASE_URL`,
  код одинаковый (оба варианта проверены автотестом).
- Один процесс: `python -m app.main` поднимает и бота, и веб-сервер.
- Внешних сервисов не нужно: база — файл, очередей и Redis нет.

## Локальный запуск на Windows (для теста)

Ничего, кроме Python, ставить не нужно — ни Docker, ни базу данных.

1. **Установите Python** с [python.org/downloads](https://www.python.org/downloads/) — версию 3.10 или новее
   (проще всего взять самую свежую).
   При установке обязательно поставьте галочку **«Add python.exe to PATH»**.
2. **Создайте бота:** напишите [@BotFather](https://t.me/BotFather) команду `/newbot`, придумайте имя —
   он пришлёт токен вида `8123456789:AAHdq...`.
3. **Узнайте свой Telegram id:** напишите [@userinfobot](https://t.me/userinfobot), он ответит числом.
4. **Запустите `run.bat`** двойным кликом из папки проекта. При первом запуске он сам создаст
   виртуальное окружение, поставит зависимости и откроет файл `.env`.
5. **Впишите в `.env`** две строки и сохраните (Ctrl+S):

   ```
   BOT_TOKEN=8123456789:AAHdq...ваш токен...
   ADMIN_IDS=248112233
   ```

   Первую неделю откройте в боте: `/admin` → «Недели и задания» → «Неделя 1 — открыть».
   Пока ни одна неделя не открыта, участники видят «Задания скоро откроются».
6. **Запустите `run.bat` снова.** Появится строка «Запускаю бота» — можно открывать бота в Telegram
   и писать `/start`. Остановить — `Ctrl+C` в окне.

**Что можно проверить локально без каналов и без домена:** каналы модерации подключать не обязательно —
пока они не привязаны, карточки заявок и отчётов с теми же кнопками «Принять/Отклонить» и «Зачесть/Отклонить»
приходят в личку всем, чей id указан в `ADMIN_IDS`. Весь марафон работает в чате с ботом,
домен и мини-приложение не нужны.

Полный тестовый прогон: `/start` → анкета → карточка заявки придёт вам же → «Принять» → создать команду →
задание → отправить фото и заметку → «Отправить на проверку» → карточка отчёта придёт вам → «Зачесть» → баллы
в рейтинге. Панель P&C — команда `/admin`.

**Полезно знать:**

- База лежит в `data\marathon.db` и переживает перезапуски. Чтобы начать с чистого листа, закройте бота
  и удалите этот файл.
- `test.bat` прогоняет автотест логики без Telegram — удобно, чтобы убедиться, что окружение собралось.
- Повторный запуск `run.bat` ничего не ломает: окружение и настройки переиспользуются.

## Развёртывание на Render (проще всего, ничего ставить не нужно)

Весь запуск — через браузер: ни командной строки, ни сервера, ни установки Python.
Render сам забирает код из GitHub, а при каждом `git push` обновляет бота автоматически.

### Шаг 1. База данных (Neon, бесплатно и бессрочно)

База нужна отдельно: на Render бесплатная база даётся только одна на аккаунт и **удаляется через
30 дней**. Neon бесплатный и по сроку не истекает, поэтому баллы участников никуда не денутся.

1. Зайдите на [neon.tech](https://neon.tech), войдите через GitHub.
2. **Create project** — название любое, регион выберите поближе (Europe / Frankfurt).
3. Нажмите зелёную кнопку **Connect** слева вверху (или карточку «Connection string»).
4. Скопируйте строку целиком, вместе с хвостом `?sslmode=require` — бот сам приведёт её к нужному виду:
   `postgresql://neondb_owner:пароль@ep-xxx.eu-central-1.aws.neon.tech/neondb?sslmode=require`

   Подойдёт любой из двух вариантов, которые предлагает Neon — и прямое подключение,
   и режим с пулом (в адресе будет `-pooler`): бот распознаёт оба и настраивается сам.

### Шаг 2. Бот и сервис

1. Создайте бота: напишите [@BotFather](https://t.me/BotFather) команду `/newbot`, скопируйте токен.
2. Узнайте свой Telegram id: напишите [@userinfobot](https://t.me/userinfobot) — он ответит числом.
3. Зайдите на [render.com](https://render.com), войдите через **GitHub** и разрешите доступ к репозиторию.
4. Нажмите **New → Blueprint**, выберите репозиторий `we_grow_dobro` и ветку `main`.
5. Render спросит три значения:

   | Поле | Что вписать |
   |---|---|
   | `DATABASE_URL` | строка подключения из Neon (шаг 1) |
   | `BOT_TOKEN` | токен от @BotFather |
   | `ADMIN_IDS` | ваш Telegram id (через запятую можно несколько) |
   | `PC_IDS` | id сотрудников P&C — им уходят заявки и вопросы из «Помощи». Пусто = всё уходит админам |
   | `PC_USERNAME` | Telegram-логин сотрудника P&C (без @) — участник получает прямую ссылку |

6. Нажмите **Apply** и подождите 3–5 минут. Когда в логах появится строка `bot @... started` —
   открывайте бота в Telegram и пишите `/start`.

Таблицы в базе бот создаст сам при первом запуске, вручную ничего делать не нужно.

### Про бесплатный тариф

**Сервис засыпает** после 15 минут без входящих запросов, и спящий бот не отвечает.
Бот сам пингует себя раз в 10 минут, но для трёхнедельного марафона советую подстраховаться
бесплатным внешним пингером:

1. Зайдите на [cron-job.org](https://cron-job.org), зарегистрируйтесь.
2. Создайте задачу: адрес `https://ВАШ-АДРЕС.onrender.com/api/health`, интервал — каждые 10 минут.

**База Neon засыпает** при простое и просыпается за доли секунды при первом запросе — бот это
переживает без ошибок, ничего настраивать не нужно.

**После марафона** сделайте `/admin` → **📥 Экспорт Excel** и сохраните файл: там команды,
участники, все отчёты и журнал начисления баллов.

### Управление

| Действие | Где |
|---|---|
| Логи бота | Render → ваш сервис → вкладка **Logs** |
| Перезапустить | Render → **Manual Deploy → Restart service** |
| Изменить настройки | Render → **Environment**, после сохранения сервис перезапустится сам |
| Обновить код | `git push` в ветку `main` — Render выкатит сам |
| Выгрузить итоги | в боте: `/admin` → 📥 Экспорт Excel |

Каналы модерации подключать не обязательно: пока они не привязаны, карточки заявок и отчётов
приходят в личку всем, чей id указан в `ADMIN_IDS`.

## Запуск на VPS (альтернатива)

### Какой сервер брать

- **Операционная система: Ubuntu 22** (если провайдер предлагает 24.04 — берите её, но 22 полностью подходит).
  Версии постарше не годятся из-за слишком старого Python:

  | Образ | Python | Подходит |
  |---|---|---|
  | Ubuntu 18 | 3.6 | нет, к тому же снят с поддержки |
  | Ubuntu 20 | 3.8 | нет |
  | **Ubuntu 22** | **3.10** | **да**, проверено автотестом |
  | Ubuntu 24 | 3.12 | да |

  Windows брать не нужно: Windows Server съедает 1.5–2 ГБ оперативной памяти только под себя,
  стоит дороже и требует RDP.
- **Мощность:** хватает самого дешёвого тарифа — 1 ядро, 1 ГБ RAM, 10 ГБ диска. База это файл,
  ни СУБД, ни Redis не нужны.
- **Расположение:** Европа, Казахстан или любая страна, где не блокируется `api.telegram.org`.
  Если сервер в России, бот не сможет подключиться к Telegram без прокси — скрипт установки
  предупредит об этом сразу.

### Установка

Подключитесь к серверу по SSH (или через веб-консоль в панели провайдера, если SSH блокирует
корпоративная сеть) и выполните:

```bash
sudo apt update && sudo apt install -y git
git clone https://github.com/ekzotik-inc/we_grow_dobro.git
cd we_grow_dobro
sudo bash deploy.sh
```

Скрипт сам поставит Python и зависимости, проверит связь с Telegram, спросит токен от
[@BotFather](https://t.me/BotFather) и ваш Telegram id (узнать: [@userinfobot](https://t.me/userinfobot)),
создаст службу с автозапуском и запустит бота. Занимает пару минут.

После этого откройте бота в Telegram и напишите `/start`.

### Управление

| Действие | Команда |
|---|---|
| Логи в реальном времени | `journalctl -u we-grow-dobro -f` |
| Статус службы | `systemctl status we-grow-dobro` |
| Перезапустить | `sudo systemctl restart we-grow-dobro` |
| Остановить | `sudo systemctl stop we-grow-dobro` |
| Обновить код и перезапустить | `bash update.sh` |
| Изменить настройки | отредактировать `.env`, затем перезапустить службу |

Служба поднимается сама после перезагрузки сервера и перезапускается при сбое.
Исключение — ошибка в настройках (например, неверный токен): в этом случае служба останавливается
с понятным сообщением в логе, а не уходит в бесконечный цикл перезапусков.

### Важное

- **Бэкап:** единственное, что нужно сохранять, — файл `data/marathon.db`. Скачать себе:
  `scp root@ВАШ_IP:~/we_grow_dobro/data/marathon.db .`
  Скрипт `update.sh` делает копию базы автоматически перед каждым обновлением.
- **Недели открывает админ** в `/admin` → «Недели и задания». Пока ни одна не открыта,
  участники видят экран «Задания скоро откроются».
- HTTP-порт (`WEB_PORT`) нужен только хостингу для проверки живости — интерфейса там нет.

### Альтернатива: Docker

```bash
cp .env.example .env && nano .env      # заполнить BOT_TOKEN и ADMIN_IDS
docker compose up -d --build
docker compose logs -f
```

Задания из `data/tasks.json` загружаются в базу автоматически при старте (повторные запуски обновляют тексты, не ломая отчёты).

### Подключение каналов

1. Создайте два канала (можно приватных): для заявок и для результатов.
2. Добавьте бота **администратором** каждого канала с правами «Публикация сообщений» и «Изменение сообщений».
3. В боте: `/admin` → **⚙️ Каналы и настройки** → «Канал заявок» → **перешлите в бот любой пост из этого канала**.
   Бот сам определит ID, проверит доступ (отправит и удалит тестовое сообщение) и сохранит его. То же для канала результатов.
4. Кнопка «🧪 Проверить каналы» в любой момент проверяет связь.

Альтернатива — прописать `REG_CHANNEL_ID` и `RESULTS_CHANNEL_ID` в `.env`. Значение из `/admin` имеет приоритет.

### Тест до старта марафона

Откройте первую неделю в `/admin` → «Недели и задания» — можно прогнать весь сценарий (регистрация → команда →
отчёт → проверка → баллы) до старта. После проверки закройте неделю той же кнопкой.

Автотест бизнес-логики и API без Telegram:

```bash
python -m scripts.smoke_test    # на Windows: test.bat
python -m scripts.make_images   # перерисовать карточки заданий в data/images
```

## Сценарии

**Участник:** `/start` → Правила → Регистрация (имя и фамилия → телефон → желаемая команда) → заявка уходит в P&C →
после подтверждения открывается меню → Задания (вкладки недель, карточка задания с условиями зачёта) →
«Выполнить» (для заданий с опциями — выбор одной опции) → отправить фото/файлы и заметку в чат → «Отправить на проверку».
После проверки приходит уведомление; отклонённый отчёт можно переделать, пока неделя активна.

**Участник до одобрения:** после анкеты видит только статус заявки и правила. Команды и задания закрыты.

**Команды.** Создаёт, переименовывает и распускает их только админ или P&C; участник в команду не вступает
и не выходит сам — его переводит P&C из карточки участника. Задания следующей недели участнику не видны:
неделя открывается в свою дату.
После «Принять» приходит уведомление и открывается полное меню. После «Отклонить» видна причина и кнопка заполнить анкету заново.

**Админ-панель `/admin`** (доступна и вам, и сотрудникам P&C из `ADMIN_IDS`):

| Раздел | Что делает |
|---|---|
| 🔎 Отчёты на проверке | очередь с навигацией, «Показать файлы», «Зачесть», «Отклонить» (5 типовых причин или свой текст) |
| 🙋 Заявки | очередь заявок на модерации, те же кнопки, что и в канале |
| 👥 Участники | фильтры (все / без команды / на модерации / дисквалифицированные), поиск по фамилии, `@username` или tg id; карточка участника со всей историей отчётов |
| — карточка участника | принять/отклонить заявку, дисквалифицировать с причиной, восстановить, перевести в любую команду, полностью удалить из бота |
| 🏷 Команды | рейтинг, состав, переименование, расформирование (участники уведомляются, баллы сохраняются) |
| ✉️ Рассылка по сегментам | см. ниже |
| 📣 Анонс недели · ⏰ Напомнить сейчас | ручной запуск анонса заданий и напоминания тем, кто ничего не отправил |
| 📋 Задания | включить/выключить показ любого задания участникам |
| ⚙️ Каналы и настройки | привязка/отвязка обоих каналов, проверка связи, переключатели: приём заявок, приём отчётов, обязательная модерация |
| 📈 Статистика | участники, команды, воронка по неделям, число без отчётов |
| 📥 Экспорт Excel | команды, участники (со статусом модерации), отчёты, журнал баллов |

### Рассылки по сегментам

`/admin` → **✉️ Рассылка** → сегмент → текст → предпросмотр с числом получателей → отправить.
Рядом с каждым сегментом сразу показано, сколько человек в него попадает.

| Сегмент | Кто попадает |
|---|---|
| Все участники | все принятые |
| Без команды | приняты, но команду не выбрали |
| Нет отчётов на этой неделе | ни одного отправленного отчёта в текущую неделю |
| Меньше N заданий за неделю | N задаётся кнопкой (1–4) |
| Ни одного зачтённого задания | за весь марафон нет зачтённых отчётов |
| Отчёт отклонён и не переделан | есть отклонённый отчёт в текущей неделе |
| Ждут проверки отчёта | есть отчёт на проверке |
| Заявки на модерации | заполнили анкету и ждут решения |
| Дисквалифицированные | исключены из зачёта |
| Конкретная команда | выбирается кнопкой |

Рассылка идёт с троттлингом ~20 сообщений в секунду, каждая записывается в таблицу `broadcasts`.

**Автоматика (`app/scheduler.py`):** анонс 4 заданий в первый день каждой недели (`ANNOUNCE_HOUR`), напоминание
за день до дедлайна тем, у кого 0 отчётов (`REMINDER_HOUR`), ежедневный дайджест P&C о непроверенных отчётах в 18:00.

## Что стоит подготовить к запуску (из анализа файла и правил)

- В таблице две версии заданий: лист 1 (актуальная, баллы 200–500, недели 1–3) и лист 2 (черновик с другими датами
  и баллами 10–50). В бот загружен **лист 1**. Уточните у P&C, что он финальный.
- Для заданий с опциями (№6, №9) в таблице не было отдельных условий для опции «пожертвовать» в №9 — взяты по
  аналогии с №6 (скриншот чека с датой). Проверьте формулировку.
- В задании №2 сказано «прикрепить 3 фото», но перечислено 2 — в боте требуется минимум 2.
- Нужно назначить ответственных P&C (их id — в `ADMIN_IDS`) и решить, кто получает вопросы участников.
- Если участников больше 5×N, останутся неполные команды: P&C видит их в «Статистике» и может перевести людей.
- Перед стартом: открыть первую неделю в панели, проверить `TZ`, подключить оба канала и нажать «Проверить каналы»,
  прогнать сценарий с тестовым аккаунтом, сделать анонс правил через «Рассылка».
- Решите, нужна ли модерация заявок: если все сотрудники допускаются автоматически, выключите её
  в `/admin` → Каналы и настройки → «Модерация заявок». Тогда участники попадают в марафон сразу после анкеты.
