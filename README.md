# We Grow Dobro — корпоративный Telegram-бот марафона добрых дел

Бот + Telegram Web App для проведения 3-недельного марафона: регистрация участников, команды по 5 человек,
задания недели (4 в неделю, 200–500 баллов, задания с двумя опциями), отправка отчётов (фото + заметка),
проверка отчётов сотрудником P&C, начисление баллов, командный рейтинг, дисквалификация, рассылки и экспорт в Excel.

Весь интерфейс бота построен на **inline-клавиатурах с редактированием сообщения**: по нажатию кнопки бот получает
`callback_query` и делает `editMessageText`/`editMessageCaption` того же сообщения (см. `app/bot/common.py: edit`).
Когда пользователь отвечает текстом или фото, бот удаляет его сообщение и обновляет своё «якорное» сообщение
(`edit_anchor`), поэтому чат не засоряется.

## Стек

- Python 3.11+, [aiogram 3](https://docs.aiogram.dev) (бот, long polling), FastAPI + uvicorn (Web App и API),
  SQLAlchemy 2 + SQLite (`data/marathon.db`), APScheduler (анонсы/напоминания), openpyxl (экспорт).
- Один процесс: `python -m app.main` поднимает и бота, и веб-сервер.

## Быстрый запуск

1. Создайте бота в [@BotFather](https://t.me/BotFather), получите токен.
2. Узнайте Telegram id сотрудников P&C (например через [@userinfobot](https://t.me/userinfobot)).
3. Скопируйте `.env.example` в `.env` и заполните `BOT_TOKEN`, `ADMIN_IDS`, при наличии домена — `WEBAPP_URL`.
4. Запуск:

```bash
# Docker (рекомендуется)
docker compose up -d --build
docker compose logs -f

# или локально
pip install -r requirements.txt
python -m app.main
```

Задания из `data/tasks.json` загружаются в базу автоматически при старте (повторные запуски обновляют тексты, не ломая отчёты).

### Web App (мини-приложение)

Telegram открывает Web App только по **HTTPS**. Варианты:

- Домен + reverse proxy (nginx/Caddy) на порт `8080`, в `.env` укажите `WEBAPP_URL=https://ваш-домен`.
- Для теста: `cloudflared tunnel --url http://localhost:8080` или `ngrok http 8080`, полученный https-адрес — в `WEBAPP_URL`.

Если `WEBAPP_URL` пуст, бот работает полностью без приложения (кнопка просто не показывается).
Приложение показывает профиль, прогресс недели, задания с условиями, состав команды и рейтинг. Отправка файлов
идёт через чат с ботом (Mini App не может загружать файлы боту напрямую).

API проверяет подпись `initData` Telegram (`app/web/api.py: validate_init_data`), чужие запросы отбрасываются.

### Тест до старта марафона

`FORCE_WEEK=1` в `.env` принудительно открывает первую неделю — можно прогнать весь сценарий (регистрация → команда →
отчёт → проверка → баллы) до 9 сентября. Перед боевым запуском верните `FORCE_WEEK=0`.

Автотест бизнес-логики и API без Telegram:

```bash
python -m scripts.smoke_test
```

## Сценарии

**Участник:** `/start` → Правила → Регистрация (ФИО, отдел, город, подтверждение правил) → Команды (вступить в команду
с местом / создать свою / «Помощь P&C») → Задания (вкладки недель, карточка задания с условиями зачёта) →
«Выполнить» (для заданий с опциями — выбор одной опции) → отправить фото/файлы и заметку в чат → «Отправить на проверку».
После проверки приходит уведомление; отклонённый отчёт можно переделать, пока неделя активна.

**P&C:** `/admin` или кнопка «Панель P&C» → Очередь проверки (карточка отчёта, «Показать файлы», «Зачесть», «Отклонить»
с типовыми причинами или своим текстом) → Участники (карточка, дисквалификация/восстановление, перевод в команду) →
Команды → Анонс недели / Рассылка → Статистика → Экспорт Excel. Новые отчёты и запросы помощи приходят P&C сразу.

**Автоматика (`app/scheduler.py`):** анонс 4 заданий в первый день каждой недели (`ANNOUNCE_HOUR`), напоминание
за день до дедлайна тем, у кого 0 отчётов (`REMINDER_HOUR`), ежедневный дайджест P&C о непроверенных отчётах в 18:00.

## Как правила реализованы

| Правило | Реализация |
|---|---|
| 3. Команда — 5 человек | `TEAM_SIZE`, проверка при вступлении/переводе, дисквалифицированные не занимают место |
| 4. Помощь P&C с распределением | кнопка «Помощь P&C» → уведомление всем админам → «Перевести в команду» |
| 5. Обязательство дойти до конца | подтверждение правил при регистрации; смена команды после старта только через P&C |
| 6. Недели 9–15, 16–22, 23–30 сентября | `WEEK*_START/END` в `.env`, таймзона `TZ` |
| 7–8. 4 задания/неделю, 200–500 баллов, опции | `data/tasks.json`; у заданий №6 и №9 две опции, выбирается ровно одна |
| 9. Только в свою неделю | отчёт можно начать и отправить только в активную неделю |
| 10. Мин. 1, макс. 4 задания в неделю | один отчёт на задание (4 задания = максимум), напоминание при 0 отчётов |
| 11. Условия зачёта | минимум фото и обязательная заметка по каждому заданию; условия показываются в карточке и при отправке |
| 12. Проверка P&C | очередь проверки, начисление только после «Зачесть», журнал баллов |
| 13. Дисквалификация | баллы участника исключаются из командного зачёта, участник уведомляется; возможно восстановление |

## Что стоит подготовить к запуску (из анализа файла и правил)

- В таблице две версии заданий: лист 1 (актуальная, баллы 200–500, недели 1–3) и лист 2 (черновик с другими датами
  и баллами 10–50). В бот загружен **лист 1**. Уточните у P&C, что он финальный.
- Для заданий с опциями (№6, №9) в таблице не было отдельных условий для опции «пожертвовать» в №9 — взяты по
  аналогии с №6 (скриншот чека с датой). Проверьте формулировку.
- В задании №2 сказано «прикрепить 3 фото», но перечислено 2 — в боте требуется минимум 2.
- Нужно назначить ответственных P&C (их id — в `ADMIN_IDS`) и решить, кто получает вопросы участников.
- Если участников больше 5×N, останутся неполные команды: P&C видит их в «Статистике» и может перевести людей.
- Для Web App нужен HTTPS-домен (или туннель). Без него всё работает через чат.
- Перед стартом: `FORCE_WEEK=0`, проверить `TZ`, прогнать сценарий с тестовым аккаунтом, сделать анонс правил
  через «Рассылка».
