# We Grow Dobro — корпоративный Telegram-бот марафона добрых дел

Бот + Telegram Web App для проведения 3-недельного марафона: регистрация участников **с модерацией**, команды по 5 человек,
задания недели (4 в неделю, 200–500 баллов, задания с двумя опциями), отправка отчётов (фото + заметка),
**проверка заявок и отчётов прямо в двух Telegram-каналах**, начисление баллов, командный рейтинг, дисквалификация,
**рассылки по сегментам участников** и экспорт в Excel.

## Два канала модерации

| Канал | Что приходит | Кнопки | Эффект |
|---|---|---|---|
| **Канал заявок** | анкета нового участника (ФИО, отдел, город, tg id) | ✅ Принять · ❌ Отклонить | до «Принять» участник **не может** вступить в команду и отправлять отчёты |
| **Канал результатов** | файлы отчёта + карточка (участник, команда, задание, условия зачёта, заметка) | ✅ Зачесть · ❌ Отклонить | **баллы начисляются только после «Зачесть»** |

Нажимает и админ, и любой сотрудник P&C (все, чьи id в `ADMIN_IDS`, плюс отмеченные админами в базе).
Посторонний, нажавший кнопку в канале, получает отказ. После решения бот **редактирует ту же карточку**
(`editMessageText`): кнопки исчезают, в тексте остаётся кто, когда и с какой причиной решил — канал становится журналом решений.
Участнику одновременно уходит уведомление в личку.

Если канал не подключён, карточки с теми же кнопками приходят всем P&C в личку — бот работает и без каналов.

Весь интерфейс бота построен на **inline-клавиатурах с редактированием сообщения**: по нажатию кнопки бот получает
`callback_query` и делает `editMessageText`/`editMessageCaption` того же сообщения (см. `app/bot/common.py: edit`).
Когда пользователь отвечает текстом или фото, бот удаляет его сообщение и обновляет своё «якорное» сообщение
(`edit_anchor`), поэтому чат не засоряется.

## Стек

- Python 3.11+, [aiogram 3](https://docs.aiogram.dev) (бот, long polling), FastAPI + uvicorn (Web App и API),
  SQLAlchemy 2 + SQLite (`data/marathon.db`), APScheduler (анонсы/напоминания), openpyxl (экспорт).
- Один процесс: `python -m app.main` поднимает и бота, и веб-сервер.

## Быстрый запуск

1. Создайте бота в [@BotFather](https://t.me/BotFather), получите токен.
2. Узнайте Telegram id сотрудников P&C (например через [@userinfobot](https://t.me/userinfobot)).
3. Скопируйте `.env.example` в `.env` и заполните `BOT_TOKEN`, `ADMIN_IDS`, при наличии домена — `WEBAPP_URL`.
4. Запуск:

```bash
# Docker (рекомендуется)
docker compose up -d --build
docker compose logs -f

# или локально
pip install -r requirements.txt
python -m app.main
```

Задания из `data/tasks.json` загружаются в базу автоматически при старте (повторные запуски обновляют тексты, не ломая отчёты).

### Подключение каналов

1. Создайте два канала (можно приватных): для заявок и для результатов.
2. Добавьте бота **администратором** каждого канала с правами «Публикация сообщений» и «Изменение сообщений».
3. В боте: `/admin` → **⚙️ Каналы и настройки** → «Канал заявок» → **перешлите в бот любой пост из этого канала**.
   Бот сам определит ID, проверит доступ (отправит и удалит тестовое сообщение) и сохранит его. То же для канала результатов.
4. Кнопка «🧪 Проверить каналы» в любой момент проверяет связь.

Альтернатива — прописать `REG_CHANNEL_ID` и `RESULTS_CHANNEL_ID` в `.env`. Значение из `/admin` имеет приоритет.

### Web App (мини-приложение)

Telegram открывает Web App только по **HTTPS**. Варианты:

- Домен + reverse proxy (nginx/Caddy) на порт `8080`, в `.env` укажите `WEBAPP_URL=https://ваш-домен`.
- Для теста: `cloudflared tunnel --url http://localhost:8080` или `ngrok http 8080`, полученный https-адрес — в `WEBAPP_URL`.

Если `WEBAPP_URL` пуст, бот работает полностью без приложения (кнопка просто не показывается).
Приложение показывает профиль, прогресс недели, задания с условиями, состав команды и рейтинг. Отправка файлов
идёт через чат с ботом (Mini App не может загружать файлы боту напрямую).

API проверяет подпись `initData` Telegram (`app/web/api.py: validate_init_data`), чужие запросы отбрасываются.

### Тест до старта марафона

`FORCE_WEEK=1` в `.env` принудительно открывает первую неделю — можно прогнать весь сценарий (регистрация → команда →
отчёт → проверка → баллы) до 9 сентября. Перед боевым запуском верните `FORCE_WEEK=0`.

Автотест бизнес-логики и API без Telegram:

```bash
python -m scripts.smoke_test
```

## Сценарии

**Участник:** `/start` → Правила → Регистрация (ФИО, отдел, город, подтверждение правил) → Команды (вступить в команду
с местом / создать свою / «Помощь P&C») → Задания (вкладки недель, карточка задания с условиями зачёта) →
«Выполнить» (для заданий с опциями — выбор одной опции) → отправить фото/файлы и заметку в чат → «Отправить на проверку».
После проверки приходит уведомление; отклонённый отчёт можно переделать, пока неделя активна.

**Участник до одобрения:** после анкеты видит только статус заявки и правила. Команды и задания закрыты.
После «Принять» приходит уведомление и открывается полное меню. После «Отклонить» видна причина и кнопка заполнить анкету заново.

**Админ-панель `/admin`** (доступна и вам, и сотрудникам P&C из `ADMIN_IDS`):

| Раздел | Что делает |
|---|---|
| 🔎 Отчёты на проверке | очередь с навигацией, «Показать файлы», «Зачесть», «Отклонить» (5 типовых причин или свой текст) |
| 🙋 Заявки | очередь заявок на модерации, те же кнопки, что и в канале |
| 👥 Участники | фильтры (все / без команды / на модерации / дисквалифицированные), поиск по фамилии, `@username` или tg id; карточка участника со всей историей отчётов |
| — карточка участника | принять/отклонить заявку, дисквалифицировать с причиной, восстановить, перевести в любую команду |
| 🏷 Команды | рейтинг, состав, переименование, расформирование (участники уведомляются, баллы сохраняются) |
| ✉️ Рассылка по сегментам | см. ниже |
| 📣 Анонс недели · ⏰ Напомнить сейчас | ручной запуск анонса заданий и напоминания тем, кто ничего не отправил |
| 📋 Задания | включить/выключить показ любого задания участникам |
| ⚙️ Каналы и настройки | привязка/отвязка обоих каналов, проверка связи, переключатели: приём заявок, приём отчётов, обязательная модерация |
| 📈 Статистика | участники, команды, воронка по неделям, число без отчётов |
| 📥 Экспорт Excel | команды, участники (со статусом модерации), отчёты, журнал баллов |

### Рассылки по сегментам

`/admin` → **✉️ Рассылка** → сегмент → текст → предпросмотр с числом получателей → отправить.
Рядом с каждым сегментом сразу показано, сколько человек в него попадает.

| Сегмент | Кто попадает |
|---|---|
| Все участники | все принятые |
| Без команды | приняты, но команду не выбрали |
| Нет отчётов на этой неделе | ни одного отправленного отчёта в текущую неделю |
| Меньше N заданий за неделю | N задаётся кнопкой (1–4) |
| Ни одного зачтённого задания | за весь марафон нет зачтённых отчётов |
| Отчёт отклонён и не переделан | есть отклонённый отчёт в текущей неделе |
| Ждут проверки отчёта | есть отчёт на проверке |
| Заявки на модерации | заполнили анкету и ждут решения |
| Дисквалифицированные | исключены из зачёта |
| Конкретная команда | выбирается кнопкой |

Рассылка идёт с троттлингом ~20 сообщений в секунду, каждая записывается в таблицу `broadcasts`.

**Автоматика (`app/scheduler.py`):** анонс 4 заданий в первый день каждой недели (`ANNOUNCE_HOUR`), напоминание
за день до дедлайна тем, у кого 0 отчётов (`REMINDER_HOUR`), ежедневный дайджест P&C о непроверенных отчётах в 18:00.

## Как правила реализованы

| Правило | Реализация |
|---|---|
| 3. Команда — 5 человек | `TEAM_SIZE`, проверка при вступлении/переводе, дисквалифицированные не занимают место |
| 4. Помощь P&C с распределением | кнопка «Помощь P&C» → уведомление всем админам → «Перевести в команду» |
| 5. Обязательство дойти до конца | подтверждение правил при регистрации; смена команды после старта только через P&C |
| 6. Недели 9–15, 16–22, 23–30 сентября | `WEEK*_START/END` в `.env`, таймзона `TZ` |
| 7–8. 4 задания/неделю, 200–500 баллов, опции | `data/tasks.json`; у заданий №6 и №9 две опции, выбирается ровно одна |
| 9. Только в свою неделю | отчёт можно начать и отправить только в активную неделю |
| 10. Мин. 1, макс. 4 задания в неделю | один отчёт на задание (4 задания = максимум), напоминание при 0 отчётов |
| 11. Условия зачёта | минимум фото и обязательная заметка по каждому заданию; условия показываются в карточке и при отправке |
| 2. Регистрация и распределение в боте | анкета в боте + модерация P&C в канале заявок |
| 12. Проверка P&C | канал результатов и очередь в `/admin`, начисление только после «Зачесть», журнал баллов |
| 13. Дисквалификация | баллы участника исключаются из командного зачёта, участник уведомляется; возможно восстановление |

## Что стоит подготовить к запуску (из анализа файла и правил)

- В таблице две версии заданий: лист 1 (актуальная, баллы 200–500, недели 1–3) и лист 2 (черновик с другими датами
  и баллами 10–50). В бот загружен **лист 1**. Уточните у P&C, что он финальный.
- Для заданий с опциями (№6, №9) в таблице не было отдельных условий для опции «пожертвовать» в №9 — взяты по
  аналогии с №6 (скриншот чека с датой). Проверьте формулировку.
- В задании №2 сказано «прикрепить 3 фото», но перечислено 2 — в боте требуется минимум 2.
- Нужно назначить ответственных P&C (их id — в `ADMIN_IDS`) и решить, кто получает вопросы участников.
- Если участников больше 5×N, останутся неполные команды: P&C видит их в «Статистике» и может перевести людей.
- Для Web App нужен HTTPS-домен (или туннель). Без него всё работает через чат.
- Перед стартом: `FORCE_WEEK=0`, проверить `TZ`, подключить оба канала и нажать «Проверить каналы»,
  прогнать сценарий с тестовым аккаунтом, сделать анонс правил через «Рассылка».
- Решите, нужна ли модерация заявок: если все сотрудники допускаются автоматически, выключите её
  в `/admin` → Каналы и настройки → «Модерация заявок». Тогда участники попадают в марафон сразу после анкеты.
